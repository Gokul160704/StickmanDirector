# StickmanDirector workflow

Apply these rules to every new stickman video series developed in this workspace.

## Story and visual production

- Use the installed `directing-stickman-videos` skill for story development: premise, series bible, character continuity, episode arcs, narration and captions, storyboard, and scene prompts.
- Use Boords as the default production workspace for every series: organize each series as a Boords project; keep scripts and versions there; build episode storyboards as ordered frames; capture each frame's shot/action, narration or sound, reference image, and review status; and use comments, review proposals, and the review panel to resolve feedback and approve changes.
- Default to Boords' Free plan for storyboard management when its limits are sufficient; Google AI Plus does not include a Boords subscription. Check Boords' current storyboard, script, export, and AI-image limits before relying on a feature. Prioritize Flow for generated artwork and treat Boords' free AI image allowance as optional/sample use.
- Make full practical use of Boords' project, Script, storyboard, frame, comment, version, review, and Asset Library workflows to keep planning and visual decisions reviewable. Reuse project assets and continuity references across episodes; keep each episode or production pass clearly named and linked to its source script where supported.
- For proposed storyboard or script changes, show the exact proposal in the Boords panel for review before applying it. Apply changes directly only when the user explicitly asks for direct edits. Never delete frames, archive content, or perform other confirmation-gated destructive actions without the required explicit confirmation.
- Use Google Flow Agent for mood-board exploration, visual prompt refinement, and image generation/editing within the Flow project. Generate or edit images in Flow, then attach approved existing images to the corresponding Boords frames and/or Asset Library for review and continuity; Boords is not an image-generation tool.
- Use the configured GTAI-1 `flow-mcp` MCP as the default interface for Google Flow. It drives its dedicated Chrome profile; call `flow_status` first and treat its active project, references, settings, live credits, and outputs as the source of truth. If the MCP is unavailable, fall back to the signed-in Flow browser. Do not substitute Gemini image API calls, ChatGPT ImageGen, or another image service unless the user explicitly changes the tool choice. Before any credit-consuming generation, inspect the live model, credit balance, and per-output cost, then follow the approval gate below. MCP `max_credits` and `acknowledge_cost` fields are not substitutes for user approval.
- Use Google Flow as the default tool for image generation and editing, character and prop references, asset organization, and optional image-to-video animation. Do not use ChatGPT ImageGen by default; use another image tool only when the user explicitly chooses it.
- Before generating episode scenes for a new series, create and review reusable character references for every recurring character and prop references for every important recurring prop in Google Flow. Record each design, ownership, starting state, and changes across episodes in the continuity notes. Use the approved references when generating every scene; do not treat an item as newly created by the assistant if the user made it manually.
- Use the connected Boords MCP for supported Boords project, script, storyboard, frame, continuity, review, and Asset Library work. It can attach existing images but cannot generate, edit, or restyle images; use Flow for those tasks and connect approved outputs back to Boords.
- Keep a complete, current copy of the script actually used in each series' own workspace project folder (for example, `projects/<series>/script.md`), even when Boords is the collaborative source of truth. Keep the exact per-episode spoken-text files beside the generated audio and update them whenever the script changes; never leave the local project script missing or knowingly out of sync with the audio used for rendering.
- Treat Google Flow scene generations as final illustration assets, not storyboard cards or prompt summaries. Each final scene image must depict one cinematic story moment as a full-frame 16:9 illustration. Reject images containing scene headings, episode/scene numbers, labels, arrows, explanatory callouts, storyboard panels, split-screen or contact-sheet layouts, or other instruction text. Intentional in-world text is allowed only when required by the approved script and art direction. Review stills at full size and in sequence for story depiction, continuity, composition, and text artifacts before approving them.
- Default to 16:9 illustrated storytelling. Use Flow image-to-video from approved stills as the primary motion method; generate only selected shots where motion improves the story. Keep the still as the visual source of truth, preserve character and prop continuity, and review generated clips for unwanted changes before assembly. For each production, record selected source stills, video prompts, model/settings, and approved outputs. Use the local still renderer only as a fallback; do not use the retired code-drawn character animation engine.
- Always write narration in natural storytelling mode for every StickmanDirector project, including future projects. Use complete, speakable sentences with an intentional narrative voice, character perspective, emotional progression, suspense, and purposeful pacing. Do not use Caveman mode, the Caveman skill, compressed fragments, or token-saving shorthand for story premises, scripts, dialogue, narration, captions, or voice direction. This rule applies even if a general assistant preference or another workflow suggests Caveman mode.
- Read the project-root `AUDIO.md` before planning or producing narration. Continue using the established Gemini TTS workflow documented there. Use `GEMINI_API_KEY` from the Windows environment, never print, log, or request keys in chat. Google AI Plus does not guarantee Gemini API quota or cover API billing. Check current model access, API quota, billing, and price before generation. Flow visual generation does not use the Gemini API key.
- Keep characters and important props consistent across episodes using reusable reference assets and written continuity notes. Add captions during editing; keep generated artwork clear of unwanted text and reserve caption-safe space.

## Google Flow credits and approval

- The user currently has Google AI Plus. Re-check Flow model availability, credit balance, and the displayed generation cost because plan limits and model costs can change.
- Treat Google AI Plus Flow credits and Boords plan limits as separate allowances. Check the current Flow credit balance and per-generation cost in Flow before media generation, and check Boords limits in Boords before planning work that depends on a paid feature. Boords plan access is not covered by Google AI Plus.
- Before generating media that uses credits, show the selected model, number of outputs, per-generation and total estimated credit cost, and the proposed images or scenes. Wait for explicit user authorization before generating.
- Do not assume an earlier approval covers revised prompts, additional outputs, a different model, or a new paid generation batch.
- Repository policy: commit reusable workflow rules, documentation, scripts, and clean templates. Keep `projects/` episode data and `output/` media local and ignored by default; only change that policy when the user explicitly selects specific material for version control and confirms it is suitable to publish.
